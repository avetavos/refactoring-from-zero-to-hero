## คอร์สนี้คืออะไร

code แทบไม่เคยมาถึงมือเราในสภาพสะอาดเรียบร้อย ส่วนใหญ่โตขึ้นมาใต้เส้นตาย โดนแปะแก้โดยคนที่ย้ายงานไปแล้ว และสะสมทางลัดจนไม่มีใครกล้าแตะ **Refactoring** คือวินัยที่ดึงรูปทรงของ code แบบนั้นกลับมาให้อ่านออกและแก้ไหว — *โดยไม่* เปลี่ยนสิ่งที่ผู้ใช้ได้รับ

โมดูลแรกนี้ว่าด้วยแนวคิดที่อยู่เบื้องหลังการลงมือ ส่วนที่เหลือของคอร์สเป็นแคตตาล็อกท่าเฉพาะ แต่ท่าที่ไม่มีหลักการรองรับก็เป็นแค่การแก้แบบเสี่ยงดวง จบบทเรียนทั้งสี่นี้แล้วคุณจะบอกได้แม่น ๆ ว่า refactoring คืออะไร อธิบายได้ว่าคุ้มกับเวลาที่เสียไปตรงไหน และทำตามจังหวะที่คุ้มกันคุณไว้ระหว่างลงมือ

## กฎหนึ่งเดียวที่นิยามวินัยนี้

> Refactoring ปรับปรุงโครงสร้าง *ภายใน* ของ code โดยไม่เปลี่ยน behavior *ภายนอก*

ทุกอย่างในคอร์สนี้แขวนอยู่กับประโยคเดียวนั้น ถ้าคุณเปลี่ยนสิ่งที่โปรแกรมทำ — แก้บั๊ก เพิ่มฟีเจอร์ เปลี่ยน output — นั่นก็เป็นงานที่มีคุณค่า แต่ไม่ใช่ refactoring การแยกสองกิจกรรมนี้ออกจากกันนี่แหละที่ทำให้ทั้งคู่ปลอดภัย

## จังหวะที่คุณจะได้เรียนรู้

Refactoring ไม่ใช่การเขียนใหม่ยกแผงแบบฮีโร่ แต่เป็น loop แน่น ๆ ของก้าวเล็กจิ๋วที่ย้อนกลับได้ และทุกก้าวต้องผ่านการยืนยันก่อนจะไปก้าวถัดไป คุณดมกลิ่น smell เจอ เปลี่ยนเล็ก ๆ หนึ่งครั้งโดยรักษา behavior ไว้ รัน test แล้ว commit ถ้า test แดงก็ undo แล้วลองก้าวที่เล็กลงกว่าเดิม จากนั้นวนใหม่

<Mermaid code={loopDiagram} title="loop ของ refactoring: ดมกลิ่น ก้าวเล็ก ๆ ทดสอบ commit ทำซ้ำ" />

loop นี้คือจังหวะหัวใจของทุกเรื่องที่ตามมา การ refactoring ก้อนใหญ่ที่ดูน่ากลัว จริง ๆ ก็แค่ก้าวเล็ก ๆ ที่ปลอดภัยหลายร้อยก้าวต่อกันเป็นสาย

## Code Smell → โมดูล

| ประเภท code smell | ตัวอย่างจากแคตตาล็อกของ Fowler (บทที่ 3) | โมดูลที่จัดการ |
|---|---|---|
| Function ยาวและซับซ้อน | Long Function, Duplicated Code, Loops | [Composing Methods](/refactoring/th/composing-methods/) |
| Feature อยู่ผิดที่ | Feature Envy, Large Class, Message Chains | [Moving Features](/refactoring/th/moving-features/) |
| ข้อมูลไม่มีขอบเขต | Primitive Obsession, Mutable Data, Global Data | [Organizing Data](/refactoring/th/organizing-data/) |
| API เรียกใช้ยาก | Long Parameter List, Data Clumps, Mysterious Name | [Simplifying APIs](/refactoring/th/simplifying-apis/) |
| เงื่อนไขอ่านยาก | Repeated Switches, เงื่อนไขซ้อนลึก, null check ซ้ำ ๆ | [Simplifying Conditionals](/refactoring/th/simplifying-conditionals/) |
| Hierarchy ไม่ตรงความจริง | Refused Bequest, Speculative Generality, Lazy Element | [Generalization & Inheritance](/refactoring/th/generalization-and-inheritance/) |
